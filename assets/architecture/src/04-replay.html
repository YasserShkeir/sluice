Replay safety railsthree independent limits; a request must clear all three

interceptor/src/replay-policy.ts · core/src/replay-deny.ts

1 · Method

GET, HEAD and POST only. PUT / PATCH / DELETE are refused outright — they can only mutate.
→ method_not_allowed

2 · Operation

Matched against the path, query and body, because a service can POST for an ordinary read — chat.post* · admin.* · files.upload|delete · conversations.create|invite · reactions · oauth|auth.token · GraphQL mutation.
→ operation_not_allowed

3 · Budget

A process-global token bucket — 60 requests per 60s — plus single-flight serialization, shared by the CLI, the dashboard, sync and every MCP tool.
→ rate_budget_exhausted

Sluice can read your session; it cannot act as you. That property is enforced here rather than in the UI, and the same three gates apply to every step of a multi-step flow.

Build and send

cartographer/src/faithful.ts · interceptor/src/replay.ts

buildReplayRequest()

The app turns a replay action plus params into a request, reading secrets from the in-memory session.

faithful fingerprint

Headers and stable params learned by diffing the eight most recent real captures of that endpoint.

sendable headers

HTTP/2 pseudo-headers (:method, :authority) and non-byte values are dropped — undici rejects both.

fetch

20s abort covering the body read. Any HTTP status comes back as a capture; only a network failure throws.

stored as source='replay'

Redacted, ingested and parsed like live traffic, so a replay is visible in the same table.

Multi-step flowssluice replay --flow · sluice_replay_flow

Learned offline

learn-flows clusters observed bursts into templates. MCP only reads and replays them, and templates never train on replay traffic.

Paced, not chained

Each step waits the median offset measured from the primary, capped at 2s; skipping a soft companion cannot desync the rest. Whole flow: 120s.

One extra rail

Each step is also checked against the owning adapter's host list, and an unresolvable path id fails the build rather than guessing.

Credential refresh sits above the rails, never inside them: on an auth failure the session is re-extracted once and the request rebuilt from the fresh one — both attempts recorded. A flow restarts from the top rather than resuming, because earlier steps may already have bound the stale session.
