sluice serve

Dashboard + API. The engine starts idle — you start it from the UI. Adds --isolated, --ingest and --terminal.

sluice start

serve, plus the MITM engine immediately. Prints the --proxy-server line to route a desktop app; it never sets the system proxy for you.

sluice capture

Passive CDP capture in a dedicated Chrome. No proxy, no CA, no Keychain — and no engine controls in the UI.

sluice mock

Replays a recorded NDJSON fixture through the real ingest path, credential-free.

Engine lifecycleone controller

Serialized by design

Every start, stop and proxy change queues on one promise, so a double-click cannot start two engines.

Supervised

A fresh supervisor per start: probe the proxy port every 5s, at most 5 restarts, backing off 1 → 16s.

Ordered teardown

Supervisor first, then the system proxy — cleared only if it still points at us — then the engine.

Capability secretsthree doors, three keys

read token

Gates /ws and every GET /api/*. Travels in the URL fragment, never in the served page.

pty token

Only with --terminal. Gates /pty alone — the read token cannot open a terminal.

ingest token

Only with --ingest. Gates the single POST /api/ingest the extension uses.
